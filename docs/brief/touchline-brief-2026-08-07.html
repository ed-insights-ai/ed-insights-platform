Where we are

You already built the hard part. It just can't remember anything.

ed-insights-platform is a working scraper, a 2,140-game Postgres database with 103k player-game rows and 22k parsed match events, a FastAPI service over it, and a Next.js app with a genuinely good design system behind it. The plan document even has a Phase 5 — AI: LLM-generated insights, a text-to-SQL chat panel, match predictions. It sits behind four phases of frontend work.

A Keelson rib isn't a detour from that plan. It's Phase 5 arriving first, through a door that's already built — because Keelson already has the chat, the scheduler, the provider routing, the persistence and the browser UI. What it doesn't have is anything that knows about soccer.

But before designing anything pretty, fifteen agents went and read the code and queried your live database. What they found reorders the whole plan.

What we verified

The data is lying to you in five named, reproducible ways.

Every one of these was confirmed against ed_insights on localhost, not inferred. A prettier dashboard over this is a downgrade.

✕
Season labels are wrong
Two program-seasons, 42 rows — FHSU's stored 2020 holds 24 games dated 2025, OBU's holds 18 more.
Cause: sidearm_discovery.py:42 fetches /schedule/{year} with no assertion. When that year's page is absent the site quietly serves the current season. Every source_url on those rows contains /stats/2025/. Fix is a three-line path assertion.
⚠
Matches are double-counted
176 duplicate (date, home, away) groups — one fixture scraped from both schools becomes two rows.
Every conference aggregate built on the base tables is inflated. Nothing in the schema prevents it; there is no canonical match key.
✕
School identification fails open, inverting results
A match failure is silently indistinguishable from "we are the away team" — so the opponent's score is read as the school's own.
conferences.py:69 and teams.py:79 both do is_home = _matches_pattern(g.home_team, pattern) with no third branch. 164 scored games where the pattern matches neither team slot: OKBU 150/191, SWOSU 6/188, NWOSU 4/163, SNUW 2/171, OBU 1/173, SNU 1/179. _ilike_pattern (duplicated at conferences.py:14-21 and teams.py:14) reduces "Oklahoma Baptist" to %Oklahoma%, missing the 104 home games stored as "Okla. Baptist". Filed as issue #15.
⚠
Conference play is unmarked
is_conference_game is NULL for all 2,140 rows.
So /api/conferences/{abbr}/standings has no conference filter anywhere (conferences.py:55-59) and returns an overall record labelled "standings".
⚠
Red cards are invisible outside Harding
All 43 red-card rows in the database are HU (41) and HUW (2).
Cause: sidearm_parser.py:339-348 hardcodes yellow_card for every caution row at the eleven SideArm programs. Any discipline view is structurally blind for 11 of 13 schools.

And a sixth, which is the structural one and the reason this brief exists: scripts/load_db.py:186-201 DELETEs then re-INSERTs every child row per game_id on each load. Last week's numbers are physically gone. The database can only ever tell you what is true right now.

The bet

Give the data a time axis, and everything else falls out of it.

Touchline writes one immutable Observation JSON per refresh — the canonical table, per-team aggregates, per-player season lines, a game_id → fingerprint map, and provenance, plus full per-match box lines. Roughly 2 MB per observation, ~55 MB for a season. (Corrected 8 Aug: this paragraph originally described the thin ledger — ~200 KB, ~6 MB a season — which D-01 rejected, because it cannot answer “what did we think that shot count was on Sep 6” and limits the score-mutation check to scores only.)

That single decision makes four things true that are impossible today:

Delta becomes computable

"What moved since Saturday" is a diff between two files, not a query. Always true, because nothing wrote it.

Trust becomes computable

Four of the nine integrity checks compare two observations: did a game_id change identity, did a final score mutate, did a program lose matches, is the feed stale.

Time travel is free

"Show me the table as it stood on September 6th" is just reading an older file — form strips and all.

Narration gets cheap and gated

A watermark gate reads the diff before spending a turn. A quiet Tuesday costs zero tokens and the boards still render.

Every board becomes a pure function of files on disk — fast, deterministic, testable, offline, and instantly recomposable. No board ever touches Postgres. Exactly one thing does, once per refresh: bin/observe.ts.

The weekly artifact

And on Sunday morning, a broadsheet.

Boards are for glancing. Once a week the rib publishes a dated, versioned HTML page into Keelson's full-width drawer — the thing you'd actually send someone. The layout is a deterministic function of the ledger; only the prose is generated, and it's slotted into a fixed scaffold so the archive stays a series instead of being silently redesigned every week.

The requirement you actually asked about

Keelson has no cron. Here's what it does have.

There is no schedule:, cron: or every: field anywhere in the workflow YAML schema, and no keelson schedule command. A repo-wide grep for cron returns two incidental hits. So scheduled freshness has to be assembled from three real clocks — and one obvious-looking seam is a trap.

A

The harness heartbeat used

A 30-second tick in apps/server/src/scheduler.ts re-runs any bound producer with a cadenceMs. Slows 6× when no browser tab is subscribed. Always fires with empty inputs and KEELSON_HOME as cwd.

→ Drives the six cheap board collectors. They need neither inputs nor a cwd — they read files.

B

A rib-held wall clock used

setInterval(60_000).unref() in the rib, evaluating a slot table against local time — Sun 06:00, Wed 06:00, Sat 22:00, Fri 16:00 check-only, plus a matchday 20:00–23:59 window every 30 minutes. Persists last-fired.json so a restart neither double-fires nor skips. Calls ctx.refreshWorkflow('touchline-refresh').

→ The only in-process way to get time-of-day. Unblessed territory, but chamber and squad both hold timers.

C

A launchd fallback used

keelson workflow run touchline-refresh --no-watch --json --base-url http://127.0.0.1:7878. The --base-url forces it through the running server, so it publishes the bound key exactly like [B]. Exit codes are a stable contract.

→ Belt and suspenders, because a laptop sleeps. Ship alongside the timer, not instead of it.

✕

ctx.runWorkflow the trap

It's the only seam that accepts a cwd, so two of the three design proposals chose it. It writes no run row, fires no run event, and — the finding neither critique caught — does not publish to a bound snapshot key, because bindings are keyed by definition object identity and runDefinition parses a fresh object. A refresh through it reaches the database and never reaches the screen.

→ cwd was never load-bearing anyway: every bash node already cds into the checkout.

Two landmines in the ingest DAG, both of which look completely innocuous.
① The merge step must pass the full historical year list, never [2026] — merge_all_seasons OVERWRITES all/*.parquet with only the years given, so a routine Saturday-night scrape would destroy the ten-season archive.
② The scrape node needs an explicit timeout: 900000 — the subprocess default is five minutes and 13 schools × ~20 matches × 0.5s politeness lands well past it. Without the override, every matchday window silently half-completes.
The season, week by week

Four modes, switched by reading the fixture calendar.

Preseason · now → Aug 26

One 06:00 daily pull that mostly discovers nothing — which is exactly what you want it doing before it matters. The work that counts: schools.toml has no 2026 entry for any program, so --year 2026 is doing all the work with no validation behind it. Every one of the thirteen schedule pages needs a manual dry run before Aug 27.

Weekdays in season

One 06:00 pull Sun and Wed. Boards tick on cadence but the data doesn't move, so the identical-content skip means "updated 2 days ago" is honest rather than restamped. The Dispatch fingerprint gate reads clean and no turn is bought. A quiet Tuesday costs zero tokens.

Matchday · Wed & Sat

At 20:00 the wall clock notices fixtures dated today and polls every 30 minutes, always --no-cache. Within ~30 minutes of a final whistle the score is in the header, the table has re-sorted with a new Δ, form badges shifted, odds moved, and the slate card flipped from fixture to result. Nobody clicks anything. This is the moment the design exists for.

Sunday 07:00 · November

The dispatch runs if — and only if — the watermark says something landed and the fingerprint says the table moved. In November the Race board flips to a clinch/eliminate grid, then a bracket. By December the Press Box holds ~24 observations, 14 dispatches, ~130 match pages, and a staircase chart of the season's scraping. Flat steps and all.

The debate agenda

Nine real forks. These are the ones where I could argue either side.

01

Fat ledger or thin?

The spec stores derived season state plus a fingerprint map — ~200 KB per observation, 6 MB a season, and collectors stay fast. Settled 8 Aug: fat won. But then "show me the Sep 6 table" works while "what did we think that match's shot count was on Sep 6" doesn't, and score-mutation only catches scores, not silent shot-count corrections. Full box lines would be ~2 MB per observation, ~55 MB a season.

Lean: go fat. 55 MB is nothing, and the checks you can't imagine yet are the ones you'll want in October.
02

Is the Dispatch really P5?

The phasing puts correctness, boards, scheduling and chat ahead of any designed page — on the theory that an LLM narrator over inverted records is worse than no narrator. The counter-argument, made well by one of the three proposals: the broadsheet is what decides whether this feels like a product or a dashboard, and a product nobody enjoys opening dies regardless of correctness.

The tiebreaker: would you rather have a correct table on Aug 27 or a beautiful page on Sep 10?
03

Patch the pipeline, or route around it?

The design routes around every bug — the merge node calls storage functions directly, the canon collapses duplicates, Feed Health reports the red-card mislabel rather than fixing it. That keeps the rib self-contained. But four of these are genuinely one-line fixes upstream, and fixing them makes the rib simpler and repairs the Next.js app for free.

Lean: fix the season assertion and the merge gates upstream (they're destructive), route around the rest.
04

Men's only, a hidden mode toggle, or double every region?

A surface declares static region keys, so rib:touchline:table is men's or women's, never both. Not academic: every school carrying the identity defect is a women's program — OKBU 150/191, SWOSU 6/188, NWOSU 4/163, SNUW 2/171 — against one stray game each for OBU and SNU on the men's side. Deferring women's soccer defers the defect; it does not avoid it.

Lean: men's only for 2026, decided out loud. A hidden mode toggle means the boards silently mean something different depending on a setting you can't see.
05

Is the in-process wall-clock timer worth its risk?

It runs inside the Keelson server process and shells out to uv run in a git checkout on a timer. Nothing in the rib contract forbids it and both chamber and squad hold timers — but nothing in Keelson tests that path either, and a bug there is a bug in the harness. Pure launchd is OS-supervised and one file, but gives up matchday awareness: a plist can't read the fixture calendar and decide it should poll tonight.

Lean: both from day one. They converge on the same code path, so the fallback costs almost nothing.
06

Seven programs or six?

Reconstructing NSU from opponents' box scores is genuinely lossy — their conference record is exact, but any match against a non-GAC opponent nobody else played is invisible, so their overall record isn't recoverable. A conference-only table is honest; an overall table with NSU in it isn't.

Lean: seven, conference scope only, with the badge. Publishing a six-team table as a conference table is exactly the error we convict the existing product of.
07

Should the narrator exist at all in v1?

The "since you last looked" register is deterministic — computed from the diff, always true, zero tokens. Only the Dispatch's read is generated. There's a real case for shipping only the deterministic register all season: the delta lines are the part that tells you something you didn't know, and the prose mostly restates them at greater length.

The honest question: what is the narrator adding that the diff isn't?
08

Do we ever build a /touchline tree in the Next.js app?

The bridge is already free — port 3000 passes CORS and the WS gate today. The things a board genuinely can't do are real: sparklines inside table rows, a 9-axis radar, a URL per entity you can text someone. But the port is ~1,600 lines of BoardView + ChartSection to render the same payload in a second chrome.

Lean: defer. It costs nothing to decide in November, when there's a season's worth of data worth a second chrome.
09

What happens to orphaned game_ids?

When a late-published box score reshuffles enumerate() order, old rows stay in Postgres as phantom fixtures. The canon stops boards double-counting and the stability check alarms — but anything reading base tables outside the canon still picks them up, and by November that's dozens. A sweeper is destructive in someone else's database; a soft-delete column is an alembic ownership problem.

Lean: hash the boxscore URL id upstream (~30 lines) so they never appear. Everything else is cleanup after the fact.
Considered and rejected

What we decided not to build, and why.

Three independent design proposals were generated from different angles, each adversarially verified against the real code. All three landed on the same name. These are the ideas that lost.

✕

The hybrid — rib plus a new /touchline route tree

Genuinely the closest call; it scored identically on feasibility, ambition and delight, and had the best reconnaissance in the bake-off. Rejected on one number: BoardView.tsx is 1,308 lines plus a 337-line hand-rolled chart section plus ~200 lines of region chrome. Its own risk section budgeted "roughly 400 lines" — a 4× underestimate of the one deliverable it correctly identified as load-bearing. And deferring costs nothing, because the bridge is already open.

✕

A cron entry and more Next.js pages — the do-nothing-new option

Gets you fresher wrong data. Worse, the naive version doesn't even work: pipeline-run --school HU --year 2026 is a silent no-op at the database layer, because scrape.py:103 skips the merge for a single year and load_db.py:274-280 then reads the stale all/ directory forever. You'd get a job that appears to succeed nightly and updates nothing.

✕

Database views as the correctness layer

You cannot create a view named games while the table games exists, and Game.__tablename__ = "games". Reading views would mean editing models.py plus every query body. And creating objects in a database whose alembic head DELETEs every row from all five data tables is an ownership hazard a rib shouldn't take.

✕

Workflow nodes that publish snapshots

All three proposals had a bash node "publish to the snapshot key". A bash node is a subprocess — no snapshot manager, no rib context, no module state. Replaced with an in-process write-seam tool named in the prompt node's tool whitelist, which is exactly how chamber does it.

✕

An LLM-authored HTML page

A 262 KB page can't round-trip through a tool result, and re-authoring one per tick would silently redesign it every week — the archive would stop being a series. The pages are deterministic functions of the ledger; only the prose is generated, slotted into a fixed scaffold.

✕

A starting-XI section with eleven seats

The failure mode is backwards. 3,556 team-games flag exactly 11 starters, 674 flag more (up to 22), and only 45 flag fewer. A section designed for eleven would render eighteen. Replaced: cap at 11 by minutes and surface the overflow as a warning badge — catching the defect that actually occurs.

So pinning Harding to slot 1 paints it violet on the one board that has a chart, while every other board paints it teal. The mitigation: give the tracked team slot 1 and direct-label its endpoint, fold the seventh program into the caption, and put the real teal season-arc in the Dispatch HTML where literal hex is available. Say it out loud rather than pretending the port is lossless.
The risk that matters

Nobody opens it.

Every other risk in this brief has a mitigation with a line number attached. This one doesn't. The whole design points at it: the "since you last looked" register exists precisely so that opening the tab on a Sunday morning immediately says something you didn't already know.

So here's the falsifiable failure condition, offered up front rather than discovered in December: if that register is ever empty on a Monday in October, the system failed at its actual job. That's measurable. Judge it by that, not by whether the charts are pretty.
